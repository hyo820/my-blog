# spec: 2048 게임

## 1. 기능 범위

### 게임판
- 4x4 그리드(표준 2048 규칙)를 2차원 배열(4x4, 빈 칸은 `0`)로 표현한다.

### 타일 생성
- 게임 시작 시 무작위 빈 칸 2곳에 타일을 생성한다(각각 90% 확률로 `2`, 10% 확률로 `4`).
- 유효한 이동(보드 상태가 실제로 바뀐 이동)이 일어날 때마다 빈 칸 중 하나에 새 타일을 하나 생성한다(동일한 90%/10% 확률).
- 이동으로 보드가 전혀 바뀌지 않았다면(막힌 방향으로 이동 시도) 새 타일을 생성하지 않는다.

### 이동/병합 로직
- 방향키(상하좌우) 입력 시 모든 타일을 해당 방향으로 밀착시킨다.
- 이동 경로상에서 값이 같은 두 타일이 인접하면 하나로 합쳐지며 값은 두 배가 된다.
- 한 번의 이동에서 하나의 타일은 최대 한 번만 병합된다(예: `2 2 4`를 왼쪽으로 밀면 `4 4`가 되고, 같은 이동 내에서 다시 `8`로 합쳐지지 않는다).
- 합쳐진 타일도 계속 이동 방향 끝까지 밀착한다.

### 승리 조건
- 값이 `2048`인 타일이 처음 생성되는 순간 승리로 판정하고 오버레이를 띄운다.
- 승리 후에도 "계속하기"를 선택하면 게임을 이어서 진행할 수 있다(원작 2048과 동일한 방식). 계속하기를 선택하지 않으면 새 게임으로만 재시작 가능.

### 패배 조건
- 보드에 빈 칸이 없고, 상하좌우 어느 방향으로 이동해도 인접한 동일 값 타일이 없어 병합이 불가능할 때 패배로 판정한다.

### 점수 계산
- 두 타일이 병합될 때마다 병합된 결과값(두 타일 값의 합)만큼 현재 점수에 더한다. (예: `2+2=4`가 합쳐지면 점수 +4, `8+8=16`이면 +16)
- 한 번의 이동에서 여러 쌍이 동시에 병합되면 각각의 병합 값을 모두 더한다.
- "새 게임" 시작 시 현재 점수는 0으로 초기화된다.

### 최고 점수 저장(localStorage)
- 키 이름(예: `game2048.best`)으로 최고 점수를 localStorage에 저장한다.
- 매 병합/점수 갱신 시점마다 현재 점수가 저장된 최고 점수보다 크면 최고 점수를 갱신하고 즉시 localStorage에 반영한다.
- 최고 점수는 "새 게임"을 눌러도 초기화되지 않고 유지된다(브라우저/세션이 달라져도 유지).
- localStorage 접근이 불가능한 환경(프라이빗 모드 등)에서도 게임 자체는 오류 없이 동작해야 한다(try/catch로 감싸고 실패 시 최고 점수 기능만 비활성화).

## 2. UI/UX

### 레이아웃
- 게임 페이지는 기존 사이트의 `.site-header`(제목 + 다크모드 토글) / `.content` / `.site-footer` 레이아웃 구조를 그대로 재사용한다(`src/templates.js`의 `layout()` 참고).
- `.content` 내부에 다음 요소를 세로로 배치한다: 제목, 점수판, 새 게임 버튼, 4x4 게임 그리드, (필요 시) 조작 안내 문구.
- 그리드는 `.content`의 `max-width: 720px` 안에서 정사각형을 유지하는 별도 컨테이너(예: `max-width: 420px`, 화면 폭에 맞춰 축소)로 구성한다.
- 그리드는 CSS Grid(4열 4행, `aspect-ratio: 1 / 1`인 셀)로 구현하고 셀 사이 간격(gap)을 둔다.

### 타일 색상
- 숫자별로 배경색이 다른 타일 스타일을 `assets/css/`에 새 CSS 변수로 정의한다(예: `--tile-2-bg`, `--tile-4-bg`, `--tile-8-bg` … `--tile-2048-bg`, 그리고 텍스트 색 `--tile-text` / `--tile-text-light`).
- 라이트/다크 모드 각각에 대해 `:root`(라이트)와 `:root[data-theme="dark"]` / `prefers-color-scheme: dark` 블록에 타일 색상 변수를 나눠 정의하여, 기존 다크모드 토글(`assets/js/theme.js`, `localStorage.theme`)과 자동으로 연동되게 한다.
- 값이 커질수록 색이 진해지거나 채도가 높아지는 방식으로 시각적 위계를 준다. 2048 타일은 강조색(`--color-accent`와 어울리는 별도 색)으로 눈에 띄게 한다.
- 타일 배경은 기존 `--color-code-bg`, `--color-border` 등과 톤이 부딪히지 않도록 조정한다.

### 점수판
- 그리드 위, 제목 아래에 "현재 점수"와 "최고 점수" 두 박스를 가로로 배치한다(원작 2048 스타일).
- 박스 스타일은 기존 `.tag`나 `#theme-toggle`처럼 `--color-border`, `--color-code-bg`를 사용한 둥근 사각형으로 사이트 톤을 유지한다.

### 새 게임 버튼
- 점수판 옆 또는 아래에 배치. 기존 `#theme-toggle` 버튼 스타일(테두리, 둥근 모서리, hover 시 `--color-code-bg` 배경)을 재사용/확장한다.
- 클릭 시 확인 없이 즉시 새 게임을 시작한다(진행 중인 점수는 사라지지만 최고 점수는 유지).

### 승리/패배 오버레이
- 그리드 위에 반투명 오버레이(`position: absolute`, 배경에 `--color-bg` 기반 반투명 색)를 씌우고 중앙에 메시지를 표시한다.
- 승리 시: "You Win! 🎉" 류의 메시지 + "계속하기" 버튼 + "새 게임" 버튼.
- 패배 시: "Game Over" 류의 메시지 + "새 게임" 버튼.
- 오버레이도 다크모드 변수를 사용해 라이트/다크에서 모두 가독성을 유지한다.

### 반응형
- 좁은 화면(기존 `@media (max-width: 480px)` 기준과 동일한 브레이크포인트)에서 그리드 폭이 뷰포트에 맞게 줄어들고, 타일 폰트 크기도 `clamp()` 등으로 축소되어 숫자가 겹치지 않게 한다.
- 점수판/버튼도 좁은 화면에서 줄바꿈되거나 세로 배치로 전환될 수 있게 한다.

## 3. 조작

- **키보드 방향키(필수)**: `ArrowUp` / `ArrowDown` / `ArrowLeft` / `ArrowRight`. `keydown` 이벤트에서 `event.preventDefault()`로 페이지 스크롤을 막는다.
- 이동 애니메이션/처리 중 중복 입력을 막기 위해 한 이동이 끝난 후 다음 입력을 받는 간단한 잠금 처리를 고려한다(필수는 아니지만 권장).
- **모바일 터치/스와이프 지원**: 제안하되 필수는 아니다. 지원한다면 `touchstart`/`touchend` 좌표 차이로 스와이프 방향을 판별해 동일한 이동 함수를 호출하는 방식을 제안한다. 스와이프 미지원 시에도 모바일에서 그리드가 보기 좋게 표시되어야 한다(반응형 레이아웃은 필수).

## 4. 파일 구조

프레임워크/외부 라이브러리를 전혀 도입하지 않고, 기존 `build.js` + `src/` 구조에 최소한으로 통합하는 방식을 제안한다.

### 제안 구조

```
my-blog/
├── assets/
│   ├── css/
│   │   ├── style.css          (기존, 공용 변수/레이아웃 유지)
│   │   └── game-2048.css      (신규: 그리드/타일/점수판/오버레이 전용 스타일)
│   └── js/
│       ├── theme.js           (기존, 그대로 재사용)
│       └── game-2048.js       (신규: 게임 로직 — 상태, 이동/병합, 점수, localStorage)
├── src/
│   └── templates.js           (renderGamePage() 함수 추가)
├── build.js                   (dist/game/2048/index.html 생성 단계 추가)
└── dist/                      (빌드 산출물, 기존과 동일하게 build.js가 생성)
    ├── assets/...
    └── game/
        └── 2048/
            └── index.html
```

### 통합 방식
- `assets/` 전체는 이미 `build.js`의 `copyDir(ASSETS_DIR, ...)`로 통째로 `dist/assets/`에 복사되므로, `game-2048.css`와 `game-2048.js`를 `assets/css/`, `assets/js/`에 추가하는 것만으로 별도 복사 로직 없이 자동으로 `dist/assets/`에 포함된다.
- 게임 페이지 자체는 블로그 글(`posts/*.md`)과 달리 마크다운 콘텐츠가 아니므로, `posts/`에 넣지 않는다. 대신 `src/templates.js`에 `renderGamePage()`라는 새 렌더 함수를 추가해 기존 `layout()`을 재사용한다(사이트 헤더/다크모드 토글/푸터가 자동으로 포함됨).
  - `renderGamePage()`의 본문(body)에는 제목, 점수판 마크업, 새 게임 버튼, 4x4 그리드 컨테이너, 오버레이 컨테이너의 정적 뼈대 HTML만 넣고, 실제 타일 렌더링/상태 갱신은 `game-2048.js`가 클라이언트에서 수행한다.
  - `layout()` 호출 시 `rootPath`는 `posts/<slug>/`, `tags/<tag>/`와 동일하게 2단계 깊이이므로 `'../..'`를 사용한다.
  - 게임 페이지의 `<head>`에 `game-2048.css`를, `</body>` 직전에 `game-2048.js`를 추가로 `<link>`/`<script>`로 삽입해야 하므로, `layout()` 함수가 추가 CSS/JS를 받을 수 있도록 파라미터(예: `extraStyles`, `extraScripts`)를 확장하거나, `renderGamePage()`에서 `layout()`이 만든 HTML 문자열에 태그를 삽입하는 방식 중 하나를 Work 단계에서 선택한다. 기존 페이지(`index.html`, 포스트, 태그 페이지)의 출력은 절대 바뀌지 않아야 한다.
- `build.js`의 `build()` 함수에 아래와 같은 단계를 추가한다(다른 로직 변경 없음):
  ```js
  const gameDir = path.join(DIST_DIR, 'game', '2048');
  fs.mkdirSync(gameDir, { recursive: true });
  fs.writeFileSync(path.join(gameDir, 'index.html'), renderGamePage());
  ```
- 새 npm 패키지, 프레임워크, 번들러는 도입하지 않는다. 순수 HTML/CSS/바닐라 JS만 사용하고 Node 내장 모듈(`fs`, `path`)만으로 빌드한다는 프로젝트 원칙을 그대로 따른다.

## 5. 연동 지점

- `src/templates.js`의 `layout()`이 모든 페이지(`index.html`, 포스트, 태그, 게임 페이지)에 공통으로 쓰이는 `.site-header`를 렌더링하므로, 여기에 게임으로 가는 링크(예: "🎮 2048")를 `#theme-toggle` 버튼 옆에 추가하면 **모든 페이지에서 게임 접근 가능**해진다. 이 방식을 권장한다(다른 페이지 UI 영향은 헤더에 링크 하나 추가되는 것뿐).
- 대안으로 `dist/index.html`(글 목록)에만 게임 링크 카드를 하나 추가하는 방법도 있으나, 방문자가 포스트 상세/태그 페이지에 있을 때는 접근하기 불편하므로 부수적으로만 고려한다.
- 최종 선택(헤더 링크 vs. 인덱스 전용 링크, 혹은 둘 다)은 사용자 승인 시 확정한다. 기본 제안은 "헤더에 링크 추가"이다.

## 6. 테스트 관점 (Review 단계 체크리스트)

- **타일 병합 정확성**
  - 동일 값 타일이 인접할 때만 병합되는지
  - 한 번의 이동에서 타일당 최대 1회만 병합되는지 (`2 2 4` → `4 4`, 같은 이동에서 `8`로 재병합되지 않음)
  - 병합된 타일이 이동 방향 끝까지 밀착하는지
  - 4방향(상/하/좌/우) 모두 동일한 규칙으로 동작하는지
- **점수 계산**
  - 병합 시 점수가 병합 결과값만큼 정확히 증가하는지
  - 한 이동에서 여러 쌍이 병합될 때 합산이 정확한지
  - "새 게임" 시 현재 점수가 0으로 초기화되는지
- **최고 점수(localStorage)**
  - 새로고침/브라우저 재시작 후에도 최고 점수가 유지되는지
  - 현재 점수가 최고 점수를 넘을 때만 최고 점수가 갱신되는지 (낮아지지 않는지)
  - "새 게임" 후에도 최고 점수가 유지되는지
  - localStorage 접근 불가 환경에서도 게임이 오류 없이 동작하는지
- **승패 판정**
  - `2048` 타일이 처음 생성되는 순간 승리 오버레이가 뜨는지
  - 승리 후 "계속하기" 선택 시 게임이 정상적으로 이어지는지
  - 보드가 가득 차고 어떤 방향으로도 병합이 불가능할 때만 패배 판정되는지 (빈 칸 없어도 병합 가능하면 패배가 아니어야 함)
- **키보드 반응**
  - 방향키 입력 시 페이지 스크롤이 발생하지 않는지
  - 막힌 방향으로 이동 시 보드/새 타일 생성이 일어나지 않는지(보드 불변)
  - 빠른 연속 입력 시 이중 이동/상태 꼬임이 없는지
- **다크모드**
  - 라이트/다크 각각에서 타일 색상, 점수판, 오버레이 대비(contrast)가 충분한지
  - 시스템 설정 감지 및 수동 토글(`#theme-toggle`) 전환 시 게임 화면도 함께 즉시 반영되는지
- **모바일/반응형 레이아웃**
  - 좁은 화면(예: 360px)에서 그리드가 잘리지 않고 타일 숫자가 겹치지 않는지
  - 점수판/새 게임 버튼이 좁은 화면에서도 탭하기 충분한 크기인지
- **빌드/통합**
  - `node build.js` 실행 후 `dist/game/2048/index.html`이 정상 생성되는지
  - 기존 `dist/index.html`, 포스트, 태그 페이지 출력에 변화가 없는지(회귀 없음)
  - 콘솔 오류 없음, 외부 네트워크 요청/외부 라이브러리 의존 없음
