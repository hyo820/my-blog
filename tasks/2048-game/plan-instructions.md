# 지침: 2048 게임 spec.md 작성 (Plan 단계)

## 범위
너의 작업 범위는 **`tasks/2048-game/spec.md` 파일을 작성하는 것뿐**이다.
코드를 구현하지 마라. 다른 파일을 수정하지 마라.

## 배경
이 저장소(`my-blog`)는 마크다운을 정적 HTML 블로그로 변환하는 프로젝트다.
- 프레임워크/번들러/외부 런타임 라이브러리 없음. 순수 HTML, CSS, JavaScript만 사용.
- `build.js`가 Node 내장 모듈(`fs`, `path`)만으로 `posts/*.md` → `dist/`를 생성한다.
- `assets/css/style.css`, `assets/js/theme.js`가 있고 `build.js`가 `assets/`를 `dist/assets/`로 복사한다.
- 다크모드(시스템 감지 + 수동 토글, localStorage 저장)를 지원하며 기존 CSS 변수 체계(`--color-bg`, `--color-text`, `--color-accent` 등, `assets/css/style.css` 참고)가 있다.
- npm 의존성 없음(`package.json` 없음).

## 요청 기능
사용자가 요청한 기능: **2048 게임**
- 방향키로 숫자 타일을 밀어서 합치는 퍼즐 게임 (4x4 그리드가 표준)
- 점수판(현재 점수, 최고 점수) 포함

## spec.md에 포함해야 할 내용
1. **기능 범위**: 게임 규칙(타일 생성, 이동/병합 로직, 승리(2048 타일 생성)/패배(더 이상 이동 불가) 조건), 점수 계산 방식, 최고 점수 저장 방식(localStorage).
2. **UI/UX**: 그리드 레이아웃, 타일 색상(숫자별), 점수판 위치, 새 게임 버튼, 승리/패배 시 오버레이 메시지. 기존 사이트의 다크모드/반응형 디자인 언어와 일관되게.
3. **조작**: 키보드 방향키(필수). 모바일 터치/스와이프 지원 여부는 제안하되 필수는 아님을 명시.
4. **파일 구조**: 이 프로젝트의 기존 구조(`assets/`, `src/`, `build.js`)와 어떻게 통합할지 구체적으로 제안.
   - 예: 게임을 별도 정적 페이지로 만들 것(예: `dist/game/2048/index.html`)인지, 그렇다면 소스는 어디 둘지(`game/2048/` 같은 새 최상위 디렉터리 등), `build.js`가 이를 `dist/`로 복사/생성하도록 어떻게 연결할지.
   - 새 프레임워크나 외부 라이브러리는 절대 제안하지 마라.
5. **연동 지점**: 블로그 인덱스(`dist/index.html`)나 헤더에 게임으로 가는 링크를 추가할지 여부 제안.
6. **테스트 관점**: Review 단계에서 확인해야 할 체크리스트(타일 병합 정확성, 점수 계산, 승패 판정, 키보드 반응, 다크모드, 모바일 레이아웃 등).
